<Title>Инструкция: изменения, версионирование и публикация</Title>

Эта инструкция для разработчиков: как вносить изменения в библиотеку, фиксировать их в CHANGELOG, поднимать версию и публиковать пакет и Storybook.

---

## 1. Внесение изменений

- Вносите правки в код по обычному процессу (ветки, коммиты).
- Для создания новых компонентов и стори см. **CONTRIBUTING.md** в корне репозитория (доступен только в Git).

---

## 2. Обновление CHANGELOG перед релизом

Перед каждым релизом обновите **CHANGELOG.md** в корне проекта.

- Текущие изменения накапливайте в секции **`[Unreleased]`** (можно править по ходу работы или один раз перед релизом).
- Секции внутри версии: **Added**, **Changed**, **Fixed**, **Removed**, **Security** — по необходимости.
- Пример:

```markdown
## [Unreleased]

### Added
- Страница «История версий» в Storybook на основе CHANGELOG.md
- Документация для разработчиков: инструкция по релизу (Development/Release workflow)

### Changed
- Версионирование и отображение истории через CHANGELOG.md и скрипт inline-changelog
```

Перед релизом:

1. Добавьте новый заголовок версии с датой, например: `## [0.6.0] — 2025-02-11`.
2. Перенесите содержимое из `[Unreleased]` под эту версию (или скопируйте и отредактируйте).
3. Оставьте пустую секцию `[Unreleased]` для следующих изменений.

---

## 3. Поднятие версии пакета

В корне проекта выполните (одну команду на выбор):

```bash
npm version patch   # 0.5.116 → 0.5.117 (исправления)
npm version minor   # 0.5.116 → 0.6.0   (новая функциональность без ломающих изменений)
npm version major   # 0.5.116 → 1.0.0   (ломающие изменения)
```

- Команда обновит **version** в **package.json** и создаст **git-тег** (например, `v0.6.0`).
- Убедитесь, что **CHANGELOG.md** уже обновлён под эту версию (см. п. 2).

---

## 4. Сборка и публикация пакета в npm

```bash
npm run build
npm publish
```

- Сначала собирается библиотека (`dist/`), затем пакет публикуется в npm.
- Для публикации нужны права в npm и выполненный `npm login` при необходимости.

---

## 5. Сборка и публикация Storybook

Чтобы обновить развёрнутый Storybook (и чтобы в нём отобразились новая версия и обновлённая история из CHANGELOG):

```bash
npm run storybook:build
```

- Скрипт сначала генерирует **Changelog.mdx** из **CHANGELOG.md** и версии из **package.json**, затем собирает Storybook в **storybook-static/themes/main/assets/storybook/**.
- Готовую папку **storybook-static/** нужно выложить на ваш хостинг (вручную или через CI/CD) по принятому в проекте процессу.

После деплоя пользователи увидят в Storybook актуальную версию (в шапке) и полную историю изменений в разделе **Documentation → Changelog**.

---

## 6. Краткая последовательность при релизе

1. Обновить **CHANGELOG.md**: оформить запись под новой версией, оставить `[Unreleased]` для будущих правок.
2. Поднять версию: **`npm version patch`** / **`minor`** / **`major`**.
3. Собрать и опубликовать пакет: **`npm run build`** → **`npm publish`**.
4. Собрать Storybook: **`npm run storybook:build`**.
5. Залить содержимое **storybook-static/** на хостинг по вашему процессу деплоя.
6. При необходимости запушить коммиты и теги: **`git push && git push --tags`** (если теги ещё не запушены).

---

## Полезные команды

| Действие | Команда |
|----------|--------|
| Локальный запуск Storybook (с пересборкой Changelog) | `npm run storybook` |
| Только перегенерировать Changelog.mdx | `node scripts/inline-changelog.js` |
| Сборка библиотеки | `npm run build` |
| Сборка Storybook для деплоя | `npm run storybook:build` |

История версий в Storybook всегда берётся из **CHANGELOG.md**; текущая версия в шапке — из **package.json**.
