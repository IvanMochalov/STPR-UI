<Title>Инструкция: изменения, версионирование и публикация</Title>

Эта инструкция для разработчиков: как вносить изменения в библиотеку, фиксировать их в CHANGELOG, поднимать версию и публиковать пакет и Storybook.

---

## 1. Внесение изменений

- Вносите правки в код по обычному процессу (ветки, коммиты).
- Для создания новых компонентов и стори см. **CONTRIBUTING.md** в корне репозитория ([доступен только в Git](https://github.com/IvanMochalov/STPR-UI/blob/main/CONTRIBUTING.md)).

---

## 2. Обновление CHANGELOG перед релизом

Перед каждым релизом обновите **CHANGELOG.md** в корне проекта.

- Составьте новый лог релиза, указав будущую версию (из пункта 3) и дату релиза.
- Заголовок версии оформляйте в формате: `## [x.y.z] — YYYY-MM-DD` (для планируемого релиза допустимо `IN FUTURE`).
- Используйте только секции: **Added**, **Changed**, **Fixed**, **Removed**, **Security** (не используйте `Updated` для новых записей).
- Для компонентных изменений фиксируйте только изменения публичного API, логики поведения и визуала компонента.
- Не добавляйте в компонентные release notes Storybook-only изменения (stories/docs/examples/decorators), если они не меняют поведение поставляемого пакета.
- Для breaking-изменений добавляйте явные migration-подсказки: что удалено/переименовано и что использовать вместо этого.
- Пример:

```markdown
## [0.6.0] — 2026-03-10

### Added
- Страница «История версий» в Storybook: отображение CHANGELOG.md и текущей версии из package.json
- Скрипт `scripts/inline-changelog.js`: генерация Changelog.mdx из CHANGELOG.md перед сборкой Storybook
- Документация для разработчиков: раздел `Documentation/Development/Release workflow` — инструкция по внесению изменений, обновлению CHANGELOG, версионированию и публикации пакета и Storybook

```

## 3. Поднятие версии пакета

- Убедитесь, что **CHANGELOG.md** уже обновлён под эту версию (см. п. 2).
- Перед выбором команды оцените тип изменений:
- `patch`: исправления без расширения публичного API;
- `minor`: новая функциональность без breaking-изменений;
- `major`: breaking-изменения публичного API/поведения.

В корне проекта выполните (одну команду на выбор):

```bash
npm version patch -m "release: %s"   # 0.5.116 → 0.5.117 (исправления)
npm version minor -m "release: %s"   # 0.5.116 → 0.6.0   (новая функциональность без ломающих изменений)
npm version major -m "release: %s"   # 0.5.116 → 1.0.0   (ломающие изменения)
```

- Команда обновит **version** в **package.json** и создаст **git-тег** (например, `v0.6.0`).

---

## 4. Сборка и публикация пакета в npm

```bash
npm run build:lib
npm publish
```

- Сначала собирается библиотека (`dist/`), затем пакет публикуется в npm.
- Для публикации нужны права в npm и выполненный `npm login` при необходимости.

---

## 5. Push тегов и создание GitHub Release

После `npm version` тег существует только локально. Необходимо явно запушить коммит и тег:

```bash
git push origin main --tags
```

Затем создайте GitHub Release — без этого шага раздел **Releases** в репозитории останется пустым, даже если тег виден в git.

**Через `gh` CLI:**

```bash
gh release create v1.0.0 --notes "Release v1.0.0"
```

**Через GitHub UI:**

1. Открыть репозиторий → **Releases** → **Create a new release**.
2. В поле «Choose a tag» выбрать существующий тег (например, `v1.0.0`).
3. Заполнить описание → **Publish release**.

---

## 6. Деплой Storybook на GitHub Pages

```bash
npm run build:storybook-pages
npm run deploy-storybook-pages
```

- `build:storybook-pages` собирает Storybook с base-путём `/STPR-UI/` для GitHub Pages.
- `deploy-storybook-pages` публикует сборку в ветку `gh-pages`.
- После деплоя Storybook доступен по адресу: https://ivanmochalov.github.io/STPR-UI/

---

## 7. Краткая последовательность при релизе

1. Обновить **CHANGELOG.md**: оформить запись под новой версией.
2. Поднять версию: **`npm version patch`** / **`minor`** / **`major -m "release: %s"`**.
3. Собрать и опубликовать пакет: **`npm run build:lib`** → **`npm publish`**.
4. Запушить коммит и тег: **`git push origin main --tags`**.
5. Создать GitHub Release: **`gh release create vX.Y.Z`** или через GitHub UI.
6. Задеплоить Storybook: **`npm run build:storybook-pages`** → **`npm run deploy-storybook-pages`**.
